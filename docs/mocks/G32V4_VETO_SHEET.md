**I2 · NUMERALS — ✅ RULED: LINING FIGURES**, for the clause numbers, the tables and the reference. The headings stay Cormorant; only the figures change.

**And the ruling's own fallback did not have to be taken, which is worth one line.** The chair wrote *"`lnum` via `registerFont`, or DM Sans numerals if PDFKit won't honour the feature — the build seat derives"*. This seat derived it rather than leaving it: **the embedded Cormorant subset's `GSUB` carries `lnum` and `tnum`** — census by `fontTools` over the base64 in this very file, `GSUB features: calt ccmp dnom frac liga lnum locl numr tnum`. **I3 · THE PAPER IS DRAWN IN pt — F-40.189's cure.** The sheet is `595.28pt × 841.89pt` with margins `{top:50, bottom:50, left:60, right:60}` pt, identical to `invoicePdf.js:35` and to `contractPdf.js` today, and **every type size is declared in pt**, so a size in this file is the number that goes into `doc.fontSize()`. ## 7 · THE REFERENCE — ✅ CLOSED, option 1

**Ruled: a per-vendor sequence, `contracts.number`, on the invoice's mechanism.** The reference prints as vetoed: `DEV440/2026/0007`. The frames are unchanged; what changed is that the string is now earned.

**The mechanism, derived at `85bdac1` from `src/lib/vendor/invoices.js:75–91` and cited so sitting 2 copies the right part:**

- `vendors.invoice_prefix` `:1220` is set once, on first use, to `'TDW/' + routing_handle`.
- `vendors.invoice_counter` `:1221` is incremented **in the UPDATE**, and the number is read from **Postgres's answer** — `.update({ invoice_counter: v.invoice_counter + 1 }).select('invoice_counter').single()`. **That read-after-write is the whole of the guarantee**, and it is the part worth copying: a read-then-increment is two statements with a gap, and the gap is where two agreements get one number.
- Contracts take the same shape with **their own pair**, `vendors.contract_prefix` and `vendors.contract_counter`. A shared counter would make invoice 7 and contract 7 impossible to hold at once.

**Two sub-details the ruling does not determine, held rather than chosen.** The vetoed reference carries a **year**; the invoice mechanism has none and never resets.

1. **Does the counter reset each year?** If not, the first agreement of 2027 reads `DEV440/2027/0012` — a string shaped like a year sequence that is not one. If it does, the sequence is per-vendor-**per-year**, a different concept from the invoice's, needing its own column or a derivation from `created_at`.
2. **The padding is 4 in the vetoed reference and 2 on invoices.** Named so the difference is a decision rather than a drift.

**And one candidate finding, for the chair to mint or dismiss.** The ratified invoice frames print `TDW/2026/0041`. The mechanism above **cannot produce that string** — it produces `TDW/DEV440/01`. **The founder has been reading an invoice reference in a shape the generator does not emit.** This seat does not self-mint a finding number; it is recorded with its derivation so the chair can allocate one or rule it a mock's licence.

**The migration slot is not allocated here.** `db/migrations/` holds `0141` at this tip, so the arithmetic next-free is `0142` — and **R-40.44 gives allocation to the chair**, with G5.1 s2 possibly taking it. Sitting 2's charter names the number; this sheet does not.
